# Revision 65 validation protocol and interpretation

The qualification command is `bash papers/A2-DYN-v65-referee-response/build.sh` from the repository checkout, followed by the label-based renderer. It has no local-preflight bypass in GitHub Actions.

The source stage checks the complete pinned v63 paper tree, byte identity of all 136 inherited cores and 187 Python files, unchanged compiled appendices, all 1809 old labels, inclusion of all 139 core modules, balanced environments, resolved reference and citation names, sixteen metadata snapshots, append-only bibliography, every frozen report in the inherited chain, and the exact workflow/source payload hashes. All inherited mathematical proved-status flags remain unchanged.

The diagnostic stage reruns the inherited finite checks and new finite fixtures in both normal and optimized Python, requiring identical output. The new fixtures cover four exact reversible matrices; a one-flight geometric contact Hessian; the determinant square root; 45 quadratic/nonlinear angular cases; 36 affine exact-label cases; quarter and parallel angular cones; the necessity of affine offsets; label variation independent of label count; and a negative limit-order fixture. They do not certify an actual new Lorentz caustic realization or a uniform long-count trace estimate.

The typesetting stage compiles every retained proof with native `pdflatex`, no shell escape, and repeated passes until the auxiliary state is stable. Any unresolved reference, missing character, LaTeX/package warning or overfull box fails qualification. The receipt records the actual source tree, commit, event SHA, run ID, PDF hash and log hash. In Actions it additionally requires a clean scoped checkout whose ordinary paper tree agrees with the committed paper tree.

The renderer obtains page ranges from the actual new theorem/section labels and renders all new proof pages, the leading theorem and the first page. Its receipt records pages and hashes. Source compilation and rendering are reproducibility and presentation evidence, not mathematical proof certification or specialist review.

Execution outcomes are recorded by the generated exact-SHA receipts and workflow conclusion. This static protocol does not predeclare a future workflow outcome.
